# 德州扑克模拟训练器

一个可在手机上运行的德州扑克模拟器，用来反复练习并在每手结束后复盘自己的失误。

核心价值不在「玩牌」，而在**告诉你哪一步打错了、错在哪、亏了多少**，并通过长期统计暴露反复出现的漏洞。

## 当前状态

共 356 个测试。

②-A 完成后，引擎已经能回答复盘引擎最核心的那个问题：**给定一个局面，每个可选动作值多少 BB**。缺的是把它接到真实牌局上——AI 对手用它做决策，复盘引擎用它逐个决策点算出你亏了多少。

现阶段没有界面、没有 AI 对手、没有复盘功能。有的是一个经过验证的无界面引擎：它能发牌、裁定合法动作、跑完整的下注轮、算边池、摊牌结算，并产出可回放的手牌记录。

## 设计要点

**每手牌完全可复现。** 所有随机性来自一个字符串 seed。同样的 seed 和按钮位，牌局逐位相同。出 bug 时贴 seed 就能原样重放。`src/core/` 内禁止调用 `Math.random()`。

**对局与复盘解耦。** 一手牌结束后产出一份自包含的 `HandRecord`（所有底牌、公共牌、完整动作序列、seed）。二期的复盘引擎只吃这份记录，不碰运行中的对局状态——这样复盘规则可以独立测试，改进规则后还能对历史手牌批量重跑。`replayHandRecord()` 已验证记录足以完整复现终局。

**筹码守恒是硬不变量。** `totalChips()` 在一手牌内的任何时刻都必须恒定。这条断言挂在每个动作之后，并由一万手随机自对弈反复冲击。德扑引擎的 bug 有个恶心的特点：**它们不崩溃，只是算错**——边池分错几个 BB、结算多付一次，牌局照常进行，但复盘数据全是脏的。而复盘数据的可信度就是这个项目的全部价值。

**金额比较一律带容差。** 筹码是浮点数，`===` 和裸 `>` 都不安全。`chips.ts` 提供 `isZeroChips` / `chipsGreater` / `round2`，它是个叶子模块（零依赖），保证任何模块都能用而不产生循环依赖。

## 测试策略

正确性主要靠三种手段建立，而不是靠逐个函数写用例：

**对拍。** 牌型评估写了两份实现——一份显然正确的穷举版，一份位运算快速版。10 万组随机 7 张牌，两者结果必须逐位一致。快速版是给蒙特卡洛用的（每个决策点要评估上万手牌），慢版是标尺。

**属性测试。** 一万手随机动作自对弈，断言引擎从不死锁、不重复发牌、不出负筹码、每个动作后筹码守恒。这类测试的价值在于它会走到没人想得到的路径——本项目里边池的一个真 bug 就是 fast-check 的任意生成器撞出来的。

**外部基准。** 蒙特卡洛胜率与精确穷举对拍误差 < 1.5 个百分点，且已知值对得上公开的德扑胜率表（AA 对单个随机手 ≈85%、72o ≈34.5%、AA 对五家 ≈49%）。

### 已知的覆盖边界

- **边池分层在产品默认配置下不可达。** 固定 100BB 等额起始筹码，加上 all-in 永远投入全部筹码，导致所有活跃玩家总投入恒等，`buildPots` 每次都合并成单个池。分层代码由变额筹码的自对弈测试覆盖（3000 手中 2703 手产生多池），产品路径本身只会有一个池——这是规则的结果，不是缺陷。
- **`buildPots` 的取整假设输入是分位对齐的。** 引擎产生的投入都经过 `round2`，满足该前提；子分金额（如 0.005）不在支持范围内。
- **盲注不在动作日志里。** `startHand` 直接扣盲，`actions` 开局为空数组。任何靠累加 `Action.amount` 来重建投入的代码，对小盲和大盲都会算错——用 `HandRecord.pots` 或 `replayHandRecord()`。

估值引擎（②-A）这边：

- **EV 是单步近似，不展开未来街的博弈树。** 它能可靠指出明显错误，不该被当作 solver 的精确输出。设计文档 §12 有完整的局限清单。
- **数字带蒙特卡洛噪声。** 默认 2000 次迭代下，一个 150BB 底池上单个 EV 的标准误约 ±1.65 BB，而严重度分级的最小档是 0.2 BB。二期需要把不确定度暴露出来，或按底池大小调整迭代数。
- **隐含赔率只覆盖口袋对。** 同花听牌与开口顺听需要牌面感知的听牌检测，本代码库尚无该能力，留给 ②-B 与复盘引擎的听牌判定一并实现。在此之前这两类手牌不获得加成——宁可少算。
- **翻前范围表覆盖 19 个节点**（5 个开池 + 10 个面对开池 + 4 个面对 3bet）。未覆盖的节点 `hasNode` 返回 false，由调用方回落。其中 5 个常见的面对开池节点（如 CO 面对 UTG）尚未录入，回落会得到全范围对手，误差比表里略微不准的条目大得多——②-B 开工前应补齐。
- **多人底池按单一跟注者建模。** 弃牌率算的是「所有人都弃牌」，但赔付项按「恰好一人跟注」定价。多人局的数字精度低于单挑。
- **性能**：单挑一次估值约 70ms，6 人桌翻前约 250ms（重构后）。AI 的手机预算是 100ms，多人局仍超——翻前强度表预计算是下一个杠杆。
